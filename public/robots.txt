# robots.txt for https://ryanlindsey.me
#
# This site wants to be read by agents: crawled, cited, and answered from,
# by name. This file says so explicitly rather than leaving every crawler
# operator to guess from silence. See /llms.txt for a curated, agent-facing
# index of what is on this site, and the MCP server at
# https://mcp.ryanlindsey.me/mcp for programmatic access (a tool endpoint,
# not a page -- fetching the bare host 404s). Neither is a robots.txt
# directive; no standard formalises either one here, so these are comments,
# not machine-readable instructions.
#
# robots.txt is per-origin (RFC 9309 §2.3). This file has no effect on
# mcp.ryanlindsey.me, which is a separate origin and carries its own
# robots.txt, served by that Worker itself (workers/mcp/src/index.ts, built by
# src/lib/mcp/discovery.ts's buildMcpRobotsTxt) -- not this file, and not a
# copy of it.
#
# ---------------------------------------------------------------------------
# READ THIS BEFORE ADDING A Disallow
# ---------------------------------------------------------------------------
# RFC 9309 §2.2.1: a named `User-agent` group does NOT inherit anything
# from the `*` group below. A crawler matches exactly one group -- the
# most specific one whose token names it -- and ignores every other group
# in this file completely. Every operator named further down (ClaudeBot,
# GPTBot, and the rest) has its own group for exactly this reason: welcoming
# it by name.
#
# The consequence: today, `Allow: /` is the only directive in this file, so
# there is nothing to leak. The day someone adds `Disallow: /some-private-path`
# under `*` and reasonably assumes that covers every crawler, it will not --
# every named agent below will keep fetching that path, because its own
# group never mentions the restriction. If a path needs to be off-limits to
# everyone, add the same Disallow to every group in this file, or better,
# enforce it at the edge/WAF layer, which does not have this gap.
#
# This is also why the Content-Signal line (see below) is repeated in every
# group instead of stated once under `*`: the same non-inheritance rule
# applies to it, and a training-data reservation that silently didn't cover
# the training crawlers it names would defeat its own point.
#
# ---------------------------------------------------------------------------
# WHAT Content-Signal IS, AND IS NOT
# ---------------------------------------------------------------------------
# `Content-Signal` is a Cloudflare-authored addition to robots.txt, live
# since 2025-09-24, sitting inside a `User-agent` group alongside `Allow`.
# It is NOT part of RFC 9309, has no IETF standing (Cloudflare's own bid to
# standardise it, draft-romm-aipref-contentsignals, expired unadopted in
# April 2026), and Google is on record dismissing it: John Mueller has
# called it bloat that "has no effects whatsoever for any crawler or llm."
# The rival IETF vocabulary (aipref) is a separate, pre-consensus effort;
# its own working-group draft states in its own text that it does not yet
# reflect consensus, so this file does not ship that vocabulary either.
#
# Given all that: this line does NOT control crawling or fetching. `Allow`
# does that, and every group below sets it to `/` for every agent named
# here. `Content-Signal` is a machine-readable statement of intent that no
# crawler is obliged to honour:
#
#   search=yes     may be indexed and cited in search results and
#                  AI-assisted answers
#   ai-input=yes   may be used for retrieval/grounding at query time, e.g.
#                  answering a question about a specific page
#   ai-train=no    a reservation of rights against using this content to
#                  train or fine-tune models -- legally, this line is an
#                  EU Article 4(3) (Directive 2019/790) rights reservation,
#                  not a technical control, and nothing here can stop a
#                  crawler that trains on it anyway
#   use=reference  Cloudflare's own default since 2026-07-01, spelled out
#                  here rather than left to inherit silently
#
# `search` and `ai-input` are about being found, read, and cited right now.
# `ai-train` is a separate question about becoming training data later --
# different stakes, and deliberately not conflated here.
#
# ---------------------------------------------------------------------------
# WHY THIS FILE IS PERMISSIVE WHILE THE SITE IS noindex
# ---------------------------------------------------------------------------
# Every page here currently carries <meta name="robots" content="noindex">
# (src/layouts/Base.astro, removed at launch). This file stays wide open
# anyway (`Allow: /` everywhere), and that combination is deliberate, not a
# contradiction to "fix" by adding a Disallow before launch.
#
# Crawling and indexing are different levers. `Disallow` stops a crawler
# from fetching a page at all, which stops it from ever seeing that page's
# `noindex` tag -- the well-known trap where blocking a page in robots.txt
# is exactly how it ends up indexed anyway (a crawler with no other signal
# can still index a disallowed URL from a link pointing at it elsewhere).
# Permissive robots.txt plus `noindex` means crawlers fetch the page, read
# the tag, and correctly decline to index it. Leave this as it is until day
# 7 removes the `noindex` tag; do not add a Disallow in the meantime.
#
# No `Sitemap:` line: there is no sitemap yet (`@astrojs/sitemap` is not
# installed, and there is nothing worth indexing while the site is noindex
# sitewide). A Sitemap line pointing at a 404 would be worse than having
# none. Day 7 adds both together.

User-agent: *
Content-Signal: search=yes, ai-input=yes, ai-train=no, use=reference
Allow: /
